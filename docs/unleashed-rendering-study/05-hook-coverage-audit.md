## 7. Priority ranking — which gap is the most likely root-cause for the texture crash cascade?

Texture "crash cascade" in the current build: garbage dimensions, format mismatches, and use-after-free fallbacks all stem from the fact that the game's D3D state flows through PM4 buffers that Liberty intercepts at various levels but not comprehensively.

### 7.1 P0 — `LockTextureRect` / `UnlockTextureRect` (video.cpp:9316-9317 under `#if 0`)

**Rationale:** Without a `LockTextureRect` hook, when the game uploads texture data (RAGE's streaming system writes pixels directly into locked texture memory), the data lands in the guest address the game chose, but the host `GuestTexture` never learns those pixels exist. The host texture is created in `GTAIV_CreateTexture` but the backing store is untouched — so when `SetTexture` binds it and the shader samples, it reads the initial clear value. Combined with the `PPC_FUNC_HOOK(sub_82A55DC0)` path (which creates GuestTextures from the allocator) this can produce the "garbage dimensions, format mismatches" pattern — because the Lock hook is the point where the game tells the host the final intended format and actually writes content.

This block is disabled because of a "parameter layout" comment from 2026-03. Getting these five hooks (`sub_82A479B0`, `sub_82A47AE0`, `sub_82A47C80`, `sub_82A47E28`, `sub_82A44A98`) validated and enabled is the single cheapest way to light up ~80% of RAGE's texture pipeline.

### 7.2 P1 — `DestructResource` (sub_82BE6230 in Unleashed)

**Rationale:** Liberty never intercepts resource destruction. Every `GuestTexture`/`GuestBuffer` allocated via `GTAIV_CreateTexture` / `GTAIV_CreateVertexBuffer` / `PPC_FUNC_HOOK(sub_82A55DC0)` leaks its descriptor slot. `g_textureDescriptorAllocator` is bounded — under the current ALLOC FALLBACK storm (memory notes: ~4608 particle emitters + all the save-state texture churn), the descriptor set will overflow. Overflow corrupts neighbour descriptors, which then read garbage pointers → the classic "texture crash cascade".

Liberty needs a guest-addr hook that maps to the RAGE-equivalent destructor (needs IDA work — search 0x82A4xxxx/0x82BFxxxx for a function that takes a resource handle and `g_userHeap.Free`s it).

### 7.3 P2 — `Clear` (sub_82BFE4C8 in Unleashed)

**Rationale:** Without a `Clear` hook, framebuffer contents between frames contain whatever the previous frame wrote (host GPU doesn't clear because no command enqueued). This isn't directly a crash, but it causes cascading validation errors in Metal when the game relies on a known-clear state (e.g. depth buffer reads = far plane). Liberty's host `Clear` is defined at video.cpp:4636 but never called from a guest hook.

### 7.4 Summary of top-3

1. **Enable `LockTextureRect`/`UnlockTextureRect` and sibling lock hooks** (video.cpp:9316-9321) — requires IDA validation of register layout, then wire up.
2. **Implement `DestructResource` hook** — requires locating GTA IV's equivalent of `sub_82BE6230` in the 0x82A4xxxx D3D wrapper band; without it, every texture allocation is a descriptor leak.
3. **Implement `Clear` hook** — trivially wires the existing host `Clear` helper (video.cpp:4636) to a guest address once identified.

Also recommended but lower impact: enable `GetSurfaceDesc` (sub_82A44A98) which is in the same `#if 0` block as P0 and unblocks any caller that queries surface dimensions post-create.
